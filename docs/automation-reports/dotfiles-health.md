## Recommendations

### 1. Refresh attention badges by elapsed time, not a narrow clock window
- Evidence: `tools/herdr/lanes/needs.py:66` republishes an unchanged count only when wall-clock seconds modulo 60 are below five. Publication sets a three-minute expiry (`tools/herdr/lanes/needs.py:69`), while the loop sleeps five seconds **after** its CLI calls (`tools/herdr/lanes/needs.py:114`, `tools/herdr/lanes/needs.py:120`). Those calls add variable latency. A steady six-second cycle landing at seconds 5, 11, 17 and so on would miss every refresh window; the initial count would expire even though the publisher remains running. This is a static failure case, not an observed live outage. The existing expiry test checks the TTL argument, not timely renewal (`tests/python/test_herdr_lanes.py:531`).
- Change: replace the modulo condition with a monotonic last-success timestamp per heading and refresh after about 60 elapsed seconds. Record the timestamp only after successful publication; retain immediate updates on count changes and the existing expiry. Roughly 5–10 product lines changed and 20–30 test lines added.
- Risk: a timestamp recorded before a failed call could suppress recovery. With a fake clock and stubbed CLI, test unchanged counts across missed wall-clock windows, changed counts, failed publication and wall-clock jumps. Verify successful heartbeats remain comfortably inside the three-minute TTL without increasing timeouts or adding retries.

### 2. Let each heading publisher update only its own heading
- Evidence: each new project heading starts its own publisher (`tools/herdr/lanes/lane.py:265`, `tools/herdr/lanes/lane.py:272`), and recovery instructions require restarting one in each heading pane (`tools/herdr/README.md:136`). However, `publish()` loops over **all** headings and maintains its own cache for all of them (`tools/herdr/lanes/needs.py:57`). With N project publishers, each refresh can therefore generate N² metadata writes rather than N. A publication failure for an unrelated heading also skips drawing the current project's summary because publication and drawing share one error boundary (`tools/herdr/lanes/needs.py:114`).
- Change: pass the existing `HERDR_WORKSPACE_ID` binding into publication and select that exact heading before counting its grouped lanes. Keep the session-wide read needed to find group members, but remove writes and cached counts for unrelated headings. Roughly 5–10 product lines changed and 15–25 test lines added; no singleton service or new coordinator is needed.
- Risk: an operator may currently rely on one misplaced publisher to maintain several headings. Confirm every active project has its own running heading publisher before narrowing ownership. Test two headings with distinct groups: each invocation must write only its own ID, preserve grouped-only counting and expiry, and report a missing/non-heading binding rather than silently publishing elsewhere.
